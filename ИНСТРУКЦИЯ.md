# Инструкция: установка и запуск приложения «Статистика перевозок»

Обновлённая версия добавляет:
- **Токен-авторизацию** — пароль больше не хранится в браузере, доступ к API закрыт.
- **Регистрация отключена** — пользователей создаёт только администратор.
- **Роли**: `admin` (управляет пользователями) и `employee` (видит и заполняет все данные).
- **Защита API**, ограничение попыток входа, логирование на сервере.
- **Бэкапы** (снимок диска в панели + ежедневный pg_dump по cron).

---

## Часть 1. Что нужно для запуска

- Node.js 18+ (уже установлен) и npm.
- PostgreSQL (на сервере — обязателен; для локальной проверки тоже нужен).
- На сервере: Linux (Ubuntu/Debian), nginx, sudo.

---

## Часть 2. Подготовка базы данных (один раз)

1. Зайдите на сервер по SSH.
2. Создайте базу и пользователя PostgreSQL:

```bash
sudo -u postgres psql
```

```sql
CREATE USER transport WITH PASSWORD 'ВАШ_НАДЁЖНЫЙ_ПАРОЛЬ';
CREATE DATABASE transport OWNER transport;
\q
```

3. Примените миграции (создают таблицы, а также роли и сессии):

```bash
cd /opt/transport-stats
psql "postgres://transport:ВАШ_НАДЁЖНЫЙ_ПАРОЛЬ@localhost:5432/transport" \
  -f supabase/migrations/20260723045801_create_transport_schema.sql
psql "postgres://transport:ВАШ_НАДЁЖНЫЙ_ПАРОЛЬ@localhost:5432/transport" \
  -f supabase/migrations/20260723090000_create_expenses.sql
psql "postgres://transport:ВАШ_НАДЁЖНЫЙ_ПАРОЛЬ@localhost:5432/transport" \
  -f supabase/migrations/20260818000000_add_roles_sessions.sql
```

> **Важно:** если в вашей базе уже есть таблицы `cars`, `records`, `expenses`, `fines`,
> `invoices`, `refuels` и др. (данные вносились ранее) — первые две миграции ничего
> не пересоздадут (там `IF NOT EXISTS`), данные сохранятся. Нужна только третья
> миграция (роли + сессии). Старые таблицы `users` (если были) останутся.

## Часть 3. Настройка (.env)

В папке проекта создайте файл `.env` (образец — `.env.example`):

```bash
cd /opt/transport-stats
cp .env.example .env
nano .env
```

Заполните:

```ini
DATABASE_URL=postgres://transport:ВАШ_НАДЁЖНЫЙ_ПАРОЛЬ@localhost:5432/transport
PORT=3000
SESSION_TTL_DAYS=30
ALLOWED_ORIGIN=*
ADMIN_EMAIL=admin@ваша-компания.ru
ADMIN_PASSWORD=ПАРОЛЬ_АДМИНА_НЕ_МЕНЕЕ_8_СИМВОЛОВ
```

> `.env` не попадает в git (он в `.gitignore`). Пароль БД смените обязательно —
> в старой версии он был зашит в коде и лежал в публичном репозитории.

## Часть 4. Создание первого администратора

```bash
cd /opt/transport-stats
npm install
node scripts/create-admin.cjs
```

Будет создан (или переведён в роль admin) пользователь `ADMIN_EMAIL` с паролем `ADMIN_PASSWORD`.

## Часть 5. Запуск бэкенда (как сервис)

```bash
sudo cp deploy/transport-stats.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now transport-stats
sudo systemctl status transport-stats
```

Проверка: `curl http://127.0.0.1:3000/health` → `{"ok":true,"db":"up"}`.
Логи: `tail -f /opt/transport-stats/logs/server.log`.

---

## Часть 6. Сборка фронтенда и nginx

```bash
cd /opt/transport-stats
npm run build
```

Настройте nginx по образцу `deploy/nginx.conf` (корень сайта — `/opt/transport-stats/dist`,
`/api/` проксируется на `127.0.0.1:3000`):

```bash
sudo cp deploy/nginx.conf /etc/nginx/sites-available/transport-stats
sudo ln -s /etc/nginx/sites-available/transport-stats /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

HTTPS (рекомендуется):

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d stats.globaltruck.online
```

## Часть 7. Бэкапы данных

1. **В панели хостинга ryvds** включите ежедневный снимок диска (2 копии) — страховка всего сервера.
2. **Ежедневный pg_dump** (быстрый, только данные) — скрипт уже в проекте:

```bash
chmod +x /opt/transport-stats/scripts/backup.sh
mkdir -p /var/backups/transport
crontab -e
```

Добавьте строку (ежедневно в 03:00):

```
0 3 * * * /opt/transport-stats/scripts/backup.sh >> /var/log/transport_backup.log 2>&1
```

Восстановление из pg_dump-бэкапа:

```bash
pg_restore --clean --if-exists -d "postgres://transport:ПАРОЛЬ@localhost:5432/transport" /var/backups/transport/transport_20260818_030000.dump
```

## Часть 8. Локальный запуск для проверки (Anaconda Prompt)

Нужен локальный PostgreSQL. Команды в Anaconda Prompt:

```
# 1. Установить зависимости
npm.cmd install

# 2. Создать .env (см. Часть 3)

# 3. Применить миграции и создать админа (скрипты выше, но пути локальные)

# 4. Терминал 1 — бэкенд
node server.cjs

# 5. Терминал 2 — фронтенд (в dev-режиме /api проксируется на 3000)
npm.cmd run dev
```

Откройте `http://localhost:5173` и войдите под админом.

## Часть 9. Как пользоваться

1. Вход — только по логину и паролю, выданным администратором.
2. **Сотрудник**: видит все данные, заполняет автомобили, рейсы, расходы, счета,
   заправки, составляет отчёты. Раздела «Пользователи» у него нет.
3. **Администратор**: дополнительно видит пункт меню «Пользователи» — создаёт
   новых пользователей (email + пароль + роль) и удаляет доступ при увольнении.
   Себя удалить нельзя, последнего админа удалить нельзя.

## Что было изменено (кратко)

| Файл | Изменение |
|------|-----------|
| `server.cjs` | Токен-авторизация, роли, отключение регистрации, защита API, rate-limit, логирование, /health, env-переменные |

| `src/App.tsx`, `src/components/AppShell.tsx` | Роль в меню, раздел «Пользователи» для админа |
